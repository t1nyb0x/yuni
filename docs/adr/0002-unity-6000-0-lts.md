# ADR-0002: Unity 6000.0 LTS に固定する

- 状態: **採用**
- 決定日: 2026-08-30
- 解決する未決事項: 要件定義書 U-6
- 関連: 要件定義書 F-18-6（Packager とランタイムのバージョン一致）、NF-L-2

---

## 文脈

Yuni は Unity のバージョンを**固定しなければならない。** 選択の問題ではなく、次の 2 つの制約から要求される。

**1. 依存する 3 つのライブラリがすべて対応している版でなければならない。** UniVRM・UniWindowController・MagicaCloth2 のどれか 1 つでも動かなければ、Yuni は成立しない。

**2. AssetBundle が Unity バージョンに依存する**（要件 F-18-6）。Yuni Packager で焼いたモデルバンドルは、同じバージョンのランタイムでしか読めない。**バージョンを上げると、利用者が焼いた資産が全部読めなくなる。** 気軽に追随できない。

制約 2 のため、この決定は後から安く覆せない。ADR として残す。

---

## 決定

**Unity 6000.0 LTS（Unity 6.0）系に固定する。**

- **採用パッチ: `6000.0.82f1`**（revision `2fb0dae735e1`）。`ProjectSettings/ProjectVersion.txt` を正とし、**CI で同一バージョンを使う**
- パッチを上げるときは、下記 3 ライブラリの動作を確認してから上げる
- **マイナー以上（6000.1 以降）へは上げない。** 上げる場合はこの ADR を廃止し、利用者が焼いたモデルバンドルの再作成が必要になる旨を告知する

### 対応状況（2026-08-30 時点の調査）

| ライブラリ | 要求バージョン | Unity 6 対応 |
|---|---|---|
| [UniVRM](https://github.com/vrm-c/UniVRM) | Unity 2022.3 LTS 以降 | ✅ v0.130.1 で Unity 6.0 / 6.2 の動作報告あり |
| [MagicaCloth2](https://magicasoft.jp/en/mc2_install/) | Unity 2022.3.0f1 以降（v2.18.2 以降） | ✅ Unity 6.4 / 6.5 まで対応 |
| [UniWindowController](https://github.com/kirurobo/UniWindowController) | Unity 2021.3 以降（v0.9.7） | ✅ 作者による VRM ビューア [UniWinC_VRM](https://github.com/kirurobo/UniWinc_VRM) が **Unity 6000.0 系 + Windows 11** で動作 |

**2026-08-30 実測**: SPCR JointDynamics v2.0.11 を 6000.0.82f1 上で**無修正でコンパイル成功**（エラー 0 / 非推奨警告 4）。詳細は [ADR-0003](0003-spcr-as-default-cloth-backend.md) および `../poc/poc-1.md`。

**UniWinC_VRM の存在が決め手である。** これは UniWindowController の作者自身が作った VRM ビューアであり、透過ウィンドウ + UniVRM + Unity 6.0 + Windows という、**Yuni の外殻とまったく同じ組み合わせが動いている実例**である。詰まったときに参照できる。

---

## 検討した代替案

### 案 A: Unity 2022.3 LTS

3 ライブラリすべての最低要求を満たす、最も保守的な選択。

**却下。** サポート期間が短く、いずれ移行を強いられる。移行時に利用者のモデルバンドルが全部無効になるのだから（制約 2）、**その痛みを払う回数は少ないほどよい。** 今から始めるプロジェクトで古い LTS を選ぶ理由がない。

### 案 B: 最新の LTS（6000.3 など）

**却下。** UniVRM と UniWindowController は Unity 6.0 での動作報告が具体的だが、より新しい LTS での確認が取れていない。とくに UniWindowController は Windows API を直接叩くため、Unity 側のウィンドウ生成の変更に影響されやすい。**F-13 が動かなければ Yuni は moca の劣化版にしかならない。**

UniVRM には Unity 6000.0.58 でのコンパイルエラー報告（2025-09、master ブランチ）もあり、**新しい版を追うことに実利がない。**

### 案 C: バージョンを固定しない

**却下。** 制約 2 により不可能。利用者が焼いたモデルバンドルが読めなくなる。

---

## 影響

- **Unity の新機能を追えない。** 6000.1 以降の機能は使わない
- **バージョンを上げるときは破壊的変更として扱う。** 利用者へモデルバンドルの再作成を求めることになる。リリースノートに明記すること
- CI と開発機で Unity のバージョンがずれると、AssetBundle が静かに壊れる。**CI でバージョンを検証すること**
- パッチバージョンの差異が AssetBundle の互換性に影響するかは未確認。**PoC-2 で確かめること**（`feasibility.md` PoC-2）。影響するなら、固定の粒度をパッチまで厳格にする必要がある

---

## 備考

要件 NF-L-2 により、**MagicaCloth2 を所持しない状態でもビルドが通らなければならない。** バージョン固定はこの要件と独立している。CI は MagicaCloth2 無しでビルドするが、Unity のバージョンは同じものを使うこと。
